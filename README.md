# NetWatch

**Понятная диагностика сети в терминале — macOS, Windows и Linux.**

NetWatch развивает исходную идею mac_net_watch: следит за сетью, сопоставляет признаки сбоя и показывает, что проверить следующим. Вместо набора разрозненных команд — живой монитор с объяснениями, историей и отчётом.

## Запуск из GitHub одной командой

На **macOS или Linux**, из любой папки терминала:

```bash
curl -fsSL https://raw.githubusercontent.com/iproby/networktestby_mac/main/install.sh | bash
```

На **Windows**, в PowerShell:

```powershell
irm https://raw.githubusercontent.com/iproby/networktestby_mac/main/install.ps1 | iex
```

Установщик скачивает полный снимок приложения из GitHub, создаёт изолированную среду и сразу открывает интерфейс. Git, ручное клонирование и `sudo` не нужны. Python 3.9+ нужен; на Mac с Homebrew установщик сможет поставить Python автоматически. Первый запуск требует доступа к GitHub и PyPI.

Эти URL используют ветку `main`: обновлённые файлы `install.sh`, `install.ps1`, `bootstrap.py` и приложение должны быть опубликованы в ней. До объединения изменений можно указать ветку, тег или SHA явно:

```bash
curl -fsSL https://raw.githubusercontent.com/iproby/networktestby_mac/BRANCH_OR_SHA/install.sh | NETWATCH_REF=BRANCH_OR_SHA bash
```

Повторная команда загружает актуальный снимок из выбранной ветки и использует уже подготовленную среду, если содержимое не изменилось. Снимки хранятся отдельно, по SHA-256 скачанного архива; предыдущие версии, настройки и журналы не перезаписываются. Хеш используется как ключ кеша; загрузка защищена обычной проверкой HTTPS-сертификатов. Автоматические запросы к GitHub нужны только при запуске удалённой команды.

Параметры приложения можно передать прямо в команду:

```bash
curl -fsSL https://raw.githubusercontent.com/iproby/networktestby_mac/main/install.sh | bash -s -- --once --json --no-log
```

Установщик сохраняет доступ к клавиатуре терминала при запуске через pipe. В неинтерактивной сессии используются обычные текстовый/JSON-режимы. Относительные пути профилей и журналов считаются от папки, где вы вызвали команду.

Каталог приложения: `~/Library/Application Support/NetWatch/versions/` на macOS, `%LOCALAPPDATA%\\NetWatch\\versions\\` в Windows и `${XDG_DATA_HOME:-~/.local/share}/NetWatch/versions/` в Linux. `NETWATCH_INSTALL_DIR` позволяет выбрать другой каталог установки. Старые версии не удаляются автоматически; их можно удалить вручную, завершив запущенные из них процессы. Пользовательские журналы и отчёты находятся отдельно от каталогов версий.

## Запуск из клонированного проекта

Из папки клонированного репозитория на **macOS или Linux**:

```bash
bash install_and_run.sh
```

На **Windows** в PowerShell или cmd:

```powershell
py run.py
```

Нужен Python **3.9+**. Запуск автоматически определяет ОС, создаёт `.venv`, устанавливает зависимости и открывает интерфейс. Повторные запуски используют готовую среду. Системные пакеты Python не изменяются; `sudo` не нужен. Для первой установки необходим доступ к PyPI. На Mac без Python, но с Homebrew, shell-лаунчер установит Python через `brew install python`. Если Python и Homebrew отсутствуют, установите Python с [python.org](https://www.python.org/downloads/). На Debian/Ubuntu может потребоваться системный пакет `python3-venv`.

Другие варианты:

```bash
python3 run.py                         # macOS / Linux, если Python уже установлен
python3 run.py --once                  # один цикл текстом
python3 run.py --once --json           # один JSON-документ, без посторонних строк
python3 run.py --plain                 # непрерывный текстовый монитор
python3 run.py --list-interfaces       # доступные адаптеры
```

В Windows используйте `py` вместо `python3`, либо `start_diagnostics.cmd`. На macOS сохранены файлы `Запустить диагностику.command` и `start_diagnostics.command` для двойного клика. Старый вход `python3 mac_net_watch.py` тоже запускает новый bootstrap.

Интерфейс включается в интерактивном терминале. При перенаправлении вывода используется текстовый режим. Для стабильного вывода в скриптах передавайте `--json`. Рекомендуемые терминалы: Terminal.app/iTerm2, Windows Terminal, современные терминалы Linux. Поддерживается ширина 80 колонок: карточки перестраиваются, содержимое прокручивается. Цвет зависит от возможностей терминала; `NO_COLOR` учитывается.

## Что на экране

| Вкладка | Для чего нужна |
| --- | --- |
| **Обзор** | Состояние, основания диагноза, следующий шаг, контрольная цепочка, график TCP и download-тест |
| **Проверки** | Каждая IP-точка, DNS-запрос и сайт: время, статус, ошибка; поиск и фильтр ошибок |
| **Сеть** | ОС, адаптер, адреса, default routes, туннельные маршруты, DNS и ограничения сборщика |
| **События** | Начало, завершение и длительность инцидентов; число затронутых циклов |
| **Настройки** | Интервал, таймаут, сохранение активного профиля, расположение журнала и отчётов |

Карточки показывают фактическое состояние, медиану задержки TCP, RX/TX выбранного адаптера и долю циклов без замечаний. Нет случайных чисел, имитации замеров или декоративных процентов. До получения данных отображается прочерк.

### Управление

| Клавиша | Действие |
| --- | --- |
| `1`…`5` | Выбрать вкладку |
| `R` | Проверить сейчас, в том числе на паузе |
| `P` | Пауза / продолжить автоматический мониторинг |
| `S` | Разовый download-тест, по умолчанию до 5 МБ |
| `E` | Сохранить JSON-отчёт текущей сессии |
| `?` | Открыть справку |
| `Q` | Завершить |
| `Tab`, стрелки, `Enter` | Перемещение по элементам и подробности проверки |

Клавиши вводятся без Shift. Во время ввода текста в поле символы принадлежат этому полю; для команд выйдите из него через Tab.

Сетевые операции выполняются в фоновых задачах; интерфейс остаётся доступен. Таймаут задаётся для отдельной операции, а период наблюдения равен длительности цикла плюс интервал. Обновления не перекрываются. Уже выполняющийся цикл может завершиться после нажатия паузы. Выход во время сетевого запроса может дождаться его таймаута.

## Как трактовать результат

Проверяется цепочка **адаптер → шлюз → внешние IP → системный DNS → прямой DNS → HTTP(S) → региональные сервисы**.

- TCP-ответ `connection refused` подтверждает ответ узла, но не работу сервиса на порту; это показано в подробностях. В график задержки входят только установленные TCP-соединения.
- Роутер может фильтровать контрольные порты. Если внешние запросы проходят, это не считается доказательством поломки роутера.
- Если HTTP работает, а прямые TCP-проверки нет, NetWatch показывает различие путей, включая возможный прокси, вместо безусловного обвинения провайдера.
- Системный DNS и прямой UDP DNS — разные проверки. Сеть может запрещать публичные резолверы и при этом нормально работать через собственный DNS или DoH/DoT.
- `403`, `429`, редиректы и TLS-ошибки относятся к конкретной проверке. Ошибка одного регионального сервиса не означает падение всего интернета.
- Регион — принадлежность сервиса, а не проверенная геолокация его CDN. Набор включает Беларусь, Россию, Европу, США, Южную Америку и Азиатско-Тихоокеанский регион.
- Задержка TCP отличается от ICMP ping. Джиттер — средняя абсолютная разница соседних медиан успешных TCP-соединений, а не измерение потерь пакетов.
- Доля OK — доля выполненных циклов с успешным итогом, а не uptime всей сети. Паузы не добавляют циклы.
- Download-тест — ограниченная HTTP-загрузка до выбранного узла, не измерение скорости тарифа. Автоматические загрузки отключены; запустите тест клавишей `S`.

Диагноз является гипотезой по выбранным проверкам. Его основания и конкретные ошибки доступны на экране. NetWatch читает настройки и выполняет контрольные запросы; маршруты, DNS и VPN системы не меняет.

## Свои контрольные точки

Сохраните начальный профиль:

```bash
python3 run.py --write-config my-network.json
```

Отредактируйте JSON и запустите:

```bash
python3 run.py --config my-network.json
```

Существующий профиль не перезаписывается. Неизвестные поля, некорректные интервалы, адреса и порты вызывают понятную ошибку. Пустой список отключает соответствующую группу; оставьте хотя бы одну IP- или HTTP-точку.

Пример небольшого профиля (остальные настройки берутся по умолчанию):

```json
{
  "interval": 5,
  "timeout": 2,
  "public_endpoints": ["1.1.1.1:443", "[2606:4700:4700::1111]:443"],
  "dns_names": ["example.com"],
  "dns_servers": ["1.1.1.1", "8.8.8.8"],
  "http_urls": ["https://www.apple.com/library/test/success.html"],
  "regional_services": [
    ["BY", "Беларусь", "NBRB", "https://www.nbrb.by/"],
    ["EU", "Европа", "Europa", "https://europa.eu/"]
  ]
}
```

Разовый запуск без редактирования профиля:

```bash
python3 run.py --once --timeout 1.5 --no-regions --no-direct-dns
python3 run.py --dns-server 192.168.1.1 --dns-name example.com
python3 run.py --http-url https://example.com/ --public-endpoint 1.1.1.1:443
python3 run.py --regional-service 'BY|Беларусь|NBRB|https://www.nbrb.by/'
python3 run.py --once --speedtest --speedtest-bytes 5000000
```

Повторяемые параметры заменяют соответствующий список профиля. `--no-regions` и `--no-direct-dns` отключают группы явно. `--interface NAME` выбирает адаптер для счётчиков, но не привязывает запросы к нему: контрольные подключения используют системную маршрутизацию. Полный список параметров: `python3 run.py --help`.

## Журналы и отчёты

По умолчанию данные сохраняются в каталоге пользователя:

- macOS: `~/Library/Application Support/NetWatch/`
- Windows: `%LOCALAPPDATA%\NetWatch\`
- Linux: `$XDG_STATE_HOME/NetWatch/` или `~/.local/state/NetWatch/`

`network-diagnostics.jsonl` содержит снимки и события открытия/закрытия инцидентов. Ротация ограничивает журнал примерно 20 МБ: текущий файл и три архивных по 5 МБ. На экране хранится до 240 снимков и 200 инцидентов. Экспорт `E` сохраняет настройки, последние снимки и инциденты в `reports/`. Профиль из интерфейса сохраняет применённые настройки в новый файл.

```bash
python3 run.py --state-dir ./my-diagnostics
python3 run.py --no-log
python3 run.py --log-file ./diagnostics.jsonl --plain
```

`--no-log` отключает автоматический журнал; ручной экспорт остаётся доступен. Отчёты содержат локальные IP-адреса, имена адаптеров, контрольные URL и ошибки. Перед отправкой просмотрите содержимое. Значения переменных окружения не копируются, встроенные логин/пароль в контрольных URL не допускаются. Проверка TLS остаётся включённой.

## Платформы

| Платформа | Системный сбор |
| --- | --- |
| macOS | `route`, `netstat`, `scutil`; адреса/счётчики через psutil. Wi-Fi и Ethernet, default routes через `utun` |
| Linux | `/proc/net/route`, `/proc/net/ipv6_route`, `/etc/resolv.conf`; адреса/счётчики через psutil |
| Windows | PowerShell `Get-NetRoute`, `Get-NetIPInterface`, `Get-NetAdapter`, `Get-DnsClientServerAddress`; счётчики через psutil |

Поддерживаются IPv4 и IPv6-точки. На системе только с IPv6 замените IPv4-контрольные адреса в профиле. VPN определяется по туннельным default routes и именам адаптеров; split tunneling без default route может не отображаться. Сведения о Wi-Fi-сигнале, SSID и типе канала, для которых нужен отдельный привилегированный API, не выдумываются. Системный/браузерный прокси может отличаться от HTTP(S)-прокси окружения.

Другие ОС и мобильные терминалы не заявлены как поддерживаемые. При ограниченном доступе к системным данным приложение показывает предупреждение, а не подменяет отсутствующие сведения успешными измерениями.

## Разработка и проверки

```bash
python3 -m venv .venv
# macOS / Linux
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest -q
# Windows
.venv\Scripts\python -m pip install -e ".[test]"
.venv\Scripts\python -m pytest -q
```

Установка пакета добавляет команду `netwatch` в активную среду. `python -m netwatch` — тот же вход.

Тесты проверяют парсинг macOS/Linux/Windows, диагностику противоречивых признаков, реальные локальные TCP/HTTP-запросы, DNS-пакеты, лимит загрузки, JSON CLI, профили, ротацию, инциденты и интерфейс Textual: навигацию, паузу, фильтры, экспорт, справку и изменение размера. Для тестов не нужны публичные сайты или права администратора.

CI настроен на macOS, Windows и Linux, Python 3.9 и 3.12. Нативный сбор всегда следует проверять и на целевой машине: fixture-тесты разбора Windows/macOS не заменяют фактический запуск там.

Код разделён на `native` (ОС), `core` (модели/пробы), `diagnosis` (выводы), `engine` (циклы/сессия), `storage`, `settings`, `cli` и `tui`. Старый `mac_net_watch.py` оставлен как совместимый вход и экспорт проверенных вспомогательных функций.
