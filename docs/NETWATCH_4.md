# NetWatch 4 — реализация 20 направлений

Пользователь разрешил внедрение всех предложений. Рабочая версия находится в ветке `codex/netwatch-github-launch`; `main` автоматически не объединяется. Приложение рассчитано на терминалы macOS/Windows/Linux.

| № | Направление | Реализация / границы |
|---|---|---|
|1|Регистратор сбоев|SQLite/WAL, восстановление, хранение по сроку/размеру, архив по времени, Enter на инциденте открывает контекст ±5 минут. Большие окна прореживаются с сохранением данных до/во время/после.|
|2|Диагностика по основаниям|Статусы слоёв, отдельное unknown, альтернативные объяснения, различие прокси/прямого пути, отказ от обвинения DNS при выключенной проверке.|
|3|Качество под нагрузкой|Download/upload, одинаковая TCP-цель, idle/loaded latency, p95/джиттер, честное insufficient_data, UDP echo с HMAC через свой отражатель.|
|4|Wi-Fi|CoreWLAN на Mac; Native WLAN на Windows; proc/iw на Linux. Метрики и разрешения зависят от ОС; без Wi-Fi — unavailable. Нативное железо здесь не проверялось.|
|5|Маршрут|Ограниченные UDP TTL/ICMP error queue на Linux, traceroute/tracert на Mac/Windows, повторные пробы/RTT и сохранённые результаты. В TUI есть непрерывный MTR: живая таблица, средняя RTT/p95, накопленные ответы/пробы и остановка; окно RTT ограничено последними 1000 ответами каждого TTL. Молчание узлов не выдаётся за транзитные потери.|
|6|HTTP/TLS|Разложение времени curl, условия кода/текста, редиректы, прямой проверенный TLS-сертификат и срок действия. Без curl — ограниченный HTTP-режим.|
|7|Фон/уведомления|start/status/stop, защита от чужого/stale PID, явные LaunchAgent/systemd/Task Scheduler, пороги сбоя/восстановления, maintenance и разрывы после сна. Desktop-доставку надо проверить на целевых ОС.|
|8|Профили задач|Общий/звонки/игры/VPN/экономия, измеримая оценка контрольного пути. Реальная телеметрия медиапотоков не заявляется.|
|9|VPN до/после|Снимки, маршруты/DNS/Wi-Fi, общие TCP-цели с портами, изменение доступности/задержек. Настройки ОС не меняются.|
|10|Отчёт поддержки|Автономные HTML+JSON, график, хронология, диагностика и контекст инцидентов; обезличивание значений и URL-ключей. Произвольный текст всё равно нужно просматривать.|
|11|Норма сети|Отдельная история по отпечатку сети и целям, минимум 20 здоровых измерений, median/MAD, до 720 значений, восстановление из SQLite.|
|12|Редактор|Цели, HTTP-условия, профили задач, интервалы/бюджет/хранение в TUI. Валидация между измерениями; сохранение в новый файл. Расширенные поля доступны в JSON.|
|13|Процессы|CPU/память/подключения; nettop на Mac; частичные TCP_INFO-байты живых сокетов на Linux. **Полные байты процессов Windows/ETW не реализованы.** Неизмеренные байты не подменяются дисковым I/O.|
|14|DNS|Система, прямые UDP/TCP и wire-format DoH для A/AAAA, проверка соответствия ответа запросу. Различия CDN/split DNS не трактуются как подмена.|
|15|IPv4/IPv6/MTU|Раздельные HTTP-проверки семейств, ограниченные IPv4 DF-пробы системным ping. Точное PMTU и IPv6 PMTU не заявляются.|
|16|Вторая точка|Явный HTTP(S)-агент, свежесть снимка, ограниченные bulk endpoints/потоки/таймауты. Внешние адреса требуют TLS+токен; UDP — HMAC. Токен не уходит на другой origin при редиректе.|
|17|Вход в сеть|Гипотеза captive portal по неожиданному ответу вместо 204, альтернативы и отдельная кнопка открытия HTTP(S)-страницы.|
|18|Нативная доставка|Самостоятельный Linux-файл собран и проверен. CI/установщики/проверка SHA-256/откат подготовлены для Mac Intel/ARM, Linux x86_64, Windows x64. **Подписанный опубликованный релиз ещё не создан:** нужны сертификаты владельца, notarization и проверки чистых Mac/Windows.|
|19|Офлайн-разбор|JSON-отчёт в TUI/CLI, архив/инциденты/диагностика; живые инструменты и фон отключены. Реальная проверка replay не выполнила ни одного HTTP-запроса.|
|20|Экономия|Учитываемый HTTP-payload/контрольные операции, UTC-бюджет bulk с резервами между процессами, безопасный отказ при недоступной истории, адаптация к стабильности/батарее. Полный трафик интерфейса и заголовки не входят в бюджет тестов.|

## Проверено в этой Linux-среде

- Полный pytest: 131 passed, 1 Windows-only skip. Тесты не требуют публичных сайтов.
- Реальные локальные TCP/HTTP, bounded download/upload, DNS/DoH A/AAAA, UDP echo с правильным/неправильным HMAC, TLS с отказом недоверенному сертификату и успешным ответом после настройки доверия.
- Авторизация агента, запрет внешнего HTTP, ограничения запросов, короткая непривилегированная loopback-трассировка.
- SQLite после перезапуска, прерванные инциденты, контекст, повреждённые записи, срок/размер, бюджет между экземплярами, обезличивание/HTML и офлайн-защита.
- Реальный жизненный цикл фонового процесса, stale PID, определения служб; пользовательские службы ОС в этой среде не регистрировались.
- Textual: восемь вкладок, редактор/валидация, история, диагностика, сравнение, офлайн, навигация/экспорт и узкий терминал.
- Самостоятельный Linux-файл с Python и CA-bundle: запуск с PATH без Python/системных утилит; реальные запросы, download/upload, DoH, HTML/JSON, replay без запросов, открытие реального PTY и выход Q.
- shell-синтаксис, проверки SHA-256 и отката установщика, `pip check`.

CI для macOS/Windows настроен; результаты удалённых запусков, реальная Wi-Fi-телеметрия, desktop-уведомления и подпись должны проверяться отдельно. Эта Linux-машина наблюдает облачную сеть, а не сеть Mac пользователя.

## Что требует продолжения

Полный Windows ETW-учёт байтов процессов остаётся отдельным расширением, требующим Windows и нативной проверки привилегированного сборщика. Подпись/нотаризация и публикация самостоятельного релиза требуют учётных данных владельца; порядок описан в [RELEASING.md](RELEASING.md). Эти ограничения не мешают запуску текущего приложения из GitHub через Python.
